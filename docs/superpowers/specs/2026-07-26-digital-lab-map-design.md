# Digital Lab Map ชั้น 3 กลุ่มงานเทคนิคการแพทย์

## เป้าหมาย

สร้างแผนที่ดิจิทัลของกลุ่มงานเทคนิคการแพทย์ อาคารเฉลิมราชสมบัติ ชั้น 3 โรงพยาบาลชลบุรี จากแผนผังชุดเดียวที่ใช้ได้ทั้งบนเว็บและเอกสารพิมพ์ โดยรองรับงานหลักสี่ด้านใน Phase 1:

1. บันทึกการเข้า–ออกและปฐมนิเทศบุคคลภายนอกจาก QR ที่สำนักงานกลุ่มงานฯ
2. แสดงห้อง โซน หน่วยงาน จุดสแกนนิ้วมือ และข้อมูลบุคลากร/เครื่องมือสำหรับเจ้าหน้าที่
3. แสดงเขตควบคุมการติดเชื้อ: พื้นที่ติดเชื้อ พื้นที่สะอาด และพื้นที่เสี่ยง
4. แสดงและพิมพ์เส้นทางหนีไฟที่ผ่านการตรวจสอบแล้วตามตำแหน่ง “ท่านอยู่ที่นี่”

แผนที่ช่วยให้ผู้ใช้รู้จุดหมายและบริบทของพื้นที่ ไม่ใช่ระบบติดตามตำแหน่งแบบต่อเนื่อง และฉบับเว็บไม่ใช่ช่องทางเดียวสำหรับเหตุฉุกเฉิน

## ขอบเขต Phase 1

- แปลงแผนผังชั้น 3 เป็น SVG แบบ responsive ครบทุกห้อง โซน ประตู จุดสแกนนิ้วมือ และทางออก 3A/3B/3C
- ใช้ไฟล์ SVG และ typed map manifest ที่ version control ดูแลเป็นแหล่งจริงของ geometry และเส้นทาง
- แสดงแผนที่สาธารณะที่นำบุคคลภายนอกจากสำนักงานไปถึงจุดสแกนนิ้วมือที่ตรงกับหน่วยงานปลายทาง
- ต่อเติม Visitor Log เดิมให้ผู้ใช้บันทึกออกจากหน้า/ลิงก์เดิมบนอุปกรณ์ที่ลงทะเบียนเข้า โดยเจ้าหน้าที่ยังปิดรายการแทนได้
- เพิ่มหน้า protected `/staff/lab-map` สำหรับเจ้าหน้าที่
- รองรับมุมมองพื้นที่/หน่วยงาน บุคลากร เครื่องมือ เขตควบคุมการติดเชื้อ และความปลอดภัย
- ผูกบุคลากรรายคนกับห้อง/โซนในฐานะพื้นที่หลักหรือพื้นที่รับผิดชอบ ไม่ใช่ข้อมูลตำแหน่งแบบ real time
- ผูกเครื่องมือกับห้อง/โซน แสดงจำนวน สถานะ รายการ และลิงก์กลับไปยังทะเบียนเครื่องมือ
- สร้าง PDF/PNG ขนาด A3 และ A4 สำหรับทางหนีไฟ เขตควบคุมการติดเชื้อ และการนำทางบุคคลภายนอก
- เลือก route preset อัตโนมัติตามจุดเริ่มและจุดหมาย แต่ไม่สร้างเส้นทางหนีไฟใหม่ด้วยอัลกอริทึม

## สิ่งที่ไม่ทำใน Phase 1

- หน้าแก้ geometry แบบลากวาง
- ตำแหน่งเครื่องมือระดับโต๊ะหรือพิกัดย่อยภายในห้อง
- การติดตามตำแหน่งบุคลากรหรือผู้มาติดต่อแบบ real time
- การสร้างเส้นทางหนีไฟใหม่จาก shortest path หรือข้อมูลเหตุการณ์สด
- Heatmap อุบัติการณ์/ความเสี่ยงและการผูก WI/SOP กับพื้นที่ ซึ่งเก็บไว้เป็น Phase 2
- การสร้างห้องสมมติให้หน่วยงานที่ไม่ได้อยู่บนชั้น 3

## แบบจำลองพื้นที่

ใช้หน่วยข้อมูลต่อไปนี้:

- `PhysicalSpace`: ห้องหรือพื้นที่จริงที่กดได้บน SVG
- `SpatialZone`: กลุ่มของพื้นที่จริงหนึ่งแห่งขึ้นไป หรือพื้นที่ย่อยภายในห้อง
- `WorkUnit`: หน่วยงานจากรายการมาตรฐานเดิมของระบบ
- `SpaceWorkUnit`: ความสัมพันธ์ many-to-many ระหว่างพื้นที่/โซนกับหน่วยงาน
- `AccessPoint`: จุดสแกนนิ้วมือ ประตู หรือทางออก
- `MapStation`: จุดติดตั้งแผนผังและตำแหน่ง “ท่านอยู่ที่นี่”
- `RoutePreset`: เส้นทางที่กำหนดไว้ล่วงหน้าและผ่านการตรวจสอบ
- `MapVersion`: เวอร์ชัน วันที่มีผล ผู้ตรวจสอบ และผู้อนุมัติ

`SpatialZone` ต้องจัดกลุ่มได้หลาย `PhysicalSpace`; จึงไม่ใช้โมเดลที่บังคับว่าโซนต้องอยู่ภายในห้องเดียว

### ประเภทเขตควบคุมการติดเชื้อ

- `infectious`: พื้นที่ติดเชื้อ — สีแดงและลายเฉียง
- `clean`: พื้นที่สะอาด — สีเขียวและพื้นเรียบ
- `risk`: พื้นที่เสี่ยง — สีเหลืองและลายจุด/สัญลักษณ์เตือน

ข้อมูลชนิดพื้นที่ต้องเก็บเป็นค่า semantic ไม่อนุมานจากสี สีและลวดลายเป็นเพียงการแสดงผล เพื่อให้ฉบับขาวดำและผู้ใช้ที่แยกสีได้ยากยังอ่านได้

### สถานะประตู

- `open`: ใช้เป็นเส้นทางได้ตามปกติ
- `fingerprint_controlled`: จุดควบคุมที่เส้นทางสาธารณะต้องสิ้นสุด แต่เส้นทางเจ้าหน้าที่อาจต่อหลังจุดได้
- `permanently_locked`: แสดงตามสถานที่จริงแต่ไม่มี edge ใน route graph และห้ามใช้ทั้งเส้นทางทั่วไป ทางลัด เส้นทางสำรอง และทางหนีไฟ

ประตูบริเวณห้องควบคุมไฟฟ้าเป็น `permanently_locked` และเข้า–ออกไม่ได้

## ความสัมพันธ์หน่วยงานกับพื้นที่

### สำนักงานกลุ่มงานเทคนิคการแพทย์

- สำนักงานกลุ่มงานฯ
- ห้องหัวหน้ากลุ่มงาน
- ห้องประชุมและพื้นที่สนับสนุนที่เกี่ยวข้อง

สำนักงานเป็นจุดเริ่มต้นหลักของ Visitor Log และเส้นทางบุคคลภายนอก

### ห้องปฏิบัติการกลาง (Central Lab)

Central Lab เป็นห้องใหญ่หนึ่งห้องที่แบ่งเป็นสองโซนชัดเจน:

- โซนซ้าย: งานเคมีคลินิก + งานภูมิคุ้มกันวิทยาคลินิก
- โซนขวา: งานโลหิตวิทยาคลินิก + งานจุลทรรศนศาสตร์คลินิก

ทั้งสองโซนใช้จุดสแกนนิ้วมือคนละจุด บุคคลภายนอกที่เลือกหนึ่งในสี่งานต้องถูกนำไปยังจุดสแกนของฝั่งที่ถูกต้อง นอกจาก Central Lab แล้ว ห้องปฏิบัติการภูมิคุ้มกันวิทยาคลินิกที่แยกอยู่บนผังยังผูกกับงานภูมิคุ้มกันวิทยาคลินิกด้วย

### งานอณูชีววิทยา

- ห้องปฏิบัติการอณูชีววิทยา
- ห้องปฏิบัติการจีโนมิกส์

### งานจุลชีววิทยา

- ห้องปฏิบัติการจุลชีววิทยาคลินิก
- ห้องวินิจฉัยเชื้อ
- BSL2 Enhance
- ห้อง PCR
- ห้องเตรียมอาหารเลี้ยงเชื้อ
- ห้องเตรียมตัวอย่าง
- โซนคลังวัสดุ

`โซนคลังวัสดุ` ประกอบด้วยพื้นที่จริงสามแห่ง:

- คลังวัสดุ
- คลังวัสดุและน้ำยา
- ห้องเก็บวัสดุและน้ำยาแช่เย็น

โซน PPE เป็นพื้นที่ความปลอดภัยแยกจากโซนคลังวัสดุ และอยู่หน้าห้องปฏิบัติการภูมิคุ้มกันวิทยาคลินิกตาม geometry ล่าสุด

### งานคลังเลือด

- ห้องรับบริจาคเลือด
- ห้องแยกส่วนประกอบของเลือด
- ห้องเตรียมเลือด
- ห้องอาหารว่างสำหรับผู้บริจาคและพื้นที่สนับสนุน

### งานตรวจพิเศษและห้องปฏิบัติการตรวจต่อ

- ห้องปฏิบัติการตรวจพิเศษ

### หน่วยงานนอกแผนผังนี้

- งานบริการผู้ป่วยนอก
- ห้องปฏิบัติการศูนย์สุขภาพชุมชนเมืองชลบุรี

สองหน่วยงานนี้ยังอยู่ในระบบแต่ไม่อยู่บนแผนผังชั้น 3 จึงแสดงเป็น “หน่วยงานนอกพื้นที่แผนที่” และไม่มี `PhysicalSpace` สมมติ

พื้นที่สนับสนุนอื่นในภาพ เช่น ห้องล้างอุปกรณ์ ห้องเตรียมสารเคมี ห้องควบคุมไฟฟ้า ห้องควบคุมระบบคอมพิวเตอร์ Locker ห้องพัก ห้องน้ำ ลิฟต์ บันได และคลังต่าง ๆ ต้องยังอยู่บน SVG แม้ไม่ได้เป็นหน่วยงานอิสระ

## สถาปัตยกรรมแผนที่

### Geometry และ manifest

- SVG เก็บรูปร่างและ anchor ของพื้นที่ ประตู จุดสแกน ทางออก ป้าย และเส้นทาง
- typed manifest เก็บรหัส ความสัมพันธ์ route preset ลำดับการแสดง และ metadata ที่ต้องใช้สร้างเว็บ/เอกสารพิมพ์
- ฐานข้อมูลเก็บชื่อที่แก้ไขได้ ความสัมพันธ์กับข้อมูลธุรกิจ การกำหนดบุคลากร/เครื่องมือ และ metadata การอนุมัติ
- validator ต้องตรวจว่ารหัสใน SVG, manifest และฐานข้อมูลตรงกันก่อน build
- Git history เก็บการเปลี่ยน geometry/manifest; ฉบับที่เผยแพร่ต้องผูกกับ `MapVersion`

### เส้นทางเว็บ

- `/staff/lab-map`: หน้าเจ้าหน้าที่แบบ protected
- `/lab-map/[stationCode]`: แผนที่สาธารณะที่เปิดจาก QR บนป้ายและตั้ง “ท่านอยู่ที่นี่” ตาม station
- `/v/[token]`: Visitor Log เดิมที่สำนักงาน ต่อเติม active-visit card, แผนที่ และ self checkout

เมื่อเพิ่ม `/staff/lab-map` ต้องเพิ่ม/ตรวจ matcher ใน protected-path regex ที่ proxy/session guard ใช้ พร้อม regression test ห้ามอาศัยเพียงการซ่อนเมนู

## ประสบการณ์บุคคลภายนอก

QR หลักที่สำนักงานเปิด `/v/[token]`:

1. หากอุปกรณ์ไม่มีรายการที่ยังไม่ออก ให้เลือกแบบรายบุคคล/หมู่คณะและกรอกแบบบันทึกเข้าเดิม
2. ระบบใช้ `contact_dept` แนะนำปลายทาง แต่ผู้ใช้เปลี่ยนห้องปลายทางที่อนุญาตได้
3. หลังบันทึกเข้า หน้าเดิมเปลี่ยนเป็น active-visit card ซึ่งแสดงเวลาเข้า ปลายทาง จุดสแกน และคำแนะนำสั้น ๆ
4. ผู้ใช้เปิดแผนที่ ดูทางหนีไฟ บันทึกภาพ หรือกดบันทึกออกจากหน้าเดิมได้ ไม่ต้องสแกน QR ซ้ำ
5. ถ้าปิดหน้าแล้วเปิดลิงก์เดิมบนอุปกรณ์เดิม ระบบกู้ active-visit card จาก credential ได้

แผนที่สาธารณะต้อง:

- เริ่มจากสำนักงานหรือ `MapStation` ที่ QR ระบุ
- แสดงห้อง ชื่อหน่วยงาน จุดสแกนนิ้วมือ ทางออก และข้อมูลปฐมนิเทศที่ปลอดภัย
- นำทางบุคคลภายนอกไปถึงจุดสแกนนิ้วมือเท่านั้น
- แสดง Central Lab ฝั่งซ้าย/ขวาและเลือกจุดสแกนตามหน่วยงาน
- ไม่แสดงรายชื่อบุคลากร รายการเครื่องมือ เอกสารภายใน หรือสถิติความเสี่ยง
- ไม่ติดตามตำแหน่งต่อเนื่องและไม่คาดหวังให้ผู้ใช้ดูหน้าจอตลอดทาง

หน้าสำเร็จต้องเน้นข้อมูลแบบดูครั้งเดียว เช่น “ออกจากสำนักงาน → เลี้ยวซ้าย → ตรงไปจุดสแกน Central Lab ฝั่งซ้าย” พร้อมภาพรวมที่บันทึกเป็นภาพได้ ป้ายจริงในอาคารยังเป็นตัวนำทางหลัก

### Self checkout

- เมื่อบันทึกเข้า เซิร์ฟเวอร์สร้าง secret แบบสุ่ม เก็บเฉพาะ hash ฝั่งฐานข้อมูล และส่ง cookie แบบ `HttpOnly`, `Secure`, `SameSite=Lax` กลับอุปกรณ์
- cookie ระบุสิทธิ์กับรายการของอุปกรณ์นั้นเท่านั้นและ JavaScript อ่านไม่ได้
- การกดบันทึกออกต้องตรวจ secret, สถานะที่ยังเปิด และ token ของฟอร์ม ก่อนบันทึก `exited_at`
- บันทึก `checkout_method = 'self'` สำหรับผู้มาติดต่อ และ `checkout_method = 'staff'` พร้อม actor สำหรับเจ้าหน้าที่
- เมื่อออกสำเร็จ secret ใช้ซ้ำไม่ได้
- ห้ามมี public search ด้วยชื่อ โทรศัพท์ หรือข้อมูลส่วนบุคคล
- หาก cookie หายหรือเปลี่ยนอุปกรณ์ เจ้าหน้าที่ปิดรายการแทนได้
- ระบบไม่บันทึกออกอัตโนมัติจากการปิดหน้า timeout หรือออกจากตำแหน่ง

## หน้าเจ้าหน้าที่

หน้า `/staff/lab-map` มีแผนที่ responsive, ตัวค้นหา/ตัวกรอง และ detail panel รองรับโหมดต่อไปนี้:

### พื้นที่และหน่วยงาน

- กดห้องหรือโซนเพื่อดูชื่อ ประเภทพื้นที่ หน่วยงาน และพื้นที่ที่เกี่ยวข้อง
- เลือกหน่วยงานเพื่อไฮไลต์ทุกพื้นที่ของหน่วยงานพร้อมกัน
- กด Central Lab ได้ทั้งภาพรวม โซนซ้าย และโซนขวา
- กดโซนคลังวัสดุแล้วไฮไลต์พื้นที่จริงทั้งสามแห่ง

### บุคลากร

- ผูก profile เดิมกับห้อง/โซนเป็น `primary` หรือ `responsible`
- แสดงเฉพาะผู้ใช้ที่มีสิทธิ์ดูข้อมูลบุคลากร
- ไม่แสดงใน public projection
- ข้อมูลหมายถึงพื้นที่หลัก/พื้นที่รับผิดชอบ ไม่ใช่สถานะว่าบุคคลอยู่ในห้องขณะนั้น
- การแก้ข้อมูลใช้ form assignment ธรรมดา ไม่มี drag-and-drop และมี audit log

### เครื่องมือ

- เพิ่ม `space_id` และ `zone_id` ในทะเบียนเครื่องมือ โดยยังเก็บ `department` เดิมเพื่อ compatibility
- เพิ่มช่องห้อง/โซนในฟอร์มเครื่องมือ และ action ย้ายพื้นที่ที่มี audit log
- กดพื้นที่แล้วแสดงจำนวนเครื่องมือ สถานะ Active/ชำรุด/ใกล้ PM-CAL/รอขึ้นทะเบียน และรายชื่อเครื่องมือ
- ปุ่ม “ดูเครื่องมือทั้งหมด” เปิดทะเบียนเครื่องมือพร้อม filter พื้นที่นั้น
- แผนที่ไฮไลต์พื้นที่ที่มีรายการต้องติดตามได้
- รายการเดิมที่ยังไม่ map ต้องอยู่ใน “ยังไม่ได้กำหนดพื้นที่” และห้ามหายจากผลรวม
- ไม่เก็บพิกัดระดับโต๊ะและไม่วาด icon เครื่องแต่ละเครื่องบนแผนที่

### เขตควบคุมการติดเชื้อ

- แสดงพื้นที่ติดเชื้อ/สะอาด/เสี่ยงตาม classification ที่กำหนด
- แสดงโซน PPE จุดเปลี่ยนผ่าน และ legend ที่อ่านได้ทั้งสีและขาวดำ
- detail panel แสดงประเภทพื้นที่ งานรับผิดชอบ และข้อมูลที่ผูกไว้ในอนาคต
- สีแดงในโหมดนี้หมายถึง “พื้นที่ติดเชื้อ” ไม่ใช่เหตุฉุกเฉินหรือสถานะเครื่องมือ

### ความปลอดภัย

- แสดงจุดสแกนนิ้วมือ ทางเข้าออก โซน PPE ทางออก 3A/3B/3C และประตูล็อคถาวร
- เลือก route preset อัตโนมัติตาม `MapStation` หรือพื้นที่ที่ผู้ใช้เลือก
- แสดงเส้นทางหลักและเส้นทางสำรองที่อนุมัติไว้เท่านั้น
- การเห็นพื้นที่บนแผนที่ไม่ใช่การให้สิทธิ์เข้า BSL2, PCR หรือพื้นที่ควบคุมจริง

สิทธิ์ดูข้อมูลประกอบใช้ permission ของโมดูลต้นทาง ผู้ไม่มีสิทธิ์ทะเบียนเครื่องมือหรือบุคลากรยังดู geometry และข้อมูลพื้นที่ทั่วไปได้ แต่ API ต้องไม่ส่งรายละเอียดที่ไม่มีสิทธิ์ให้ client

## การเลือกและตรวจเส้นทาง

Route graph ต้องใช้ node/edge ที่ระบุชัดเจนใน manifest:

- visitor route: จากสำนักงาน/จุดเริ่มไปยัง fingerprint checkpoint ที่ map กับหน่วยงาน
- staff orientation route: ต่อหลัง checkpoint ได้เมื่อเป็น route ที่กำหนดไว้ แต่ไม่ถือเป็นหลักฐานสิทธิ์ทางกายภาพ
- evacuation route: จาก `MapStation` หรือโซนไปยังทางออกตาม preset ที่อนุมัติ

ระบบเลือก preset ให้ผู้ใช้ได้อัตโนมัติ แต่ห้ามสร้าง evacuation route ใหม่จาก shortest-path algorithm เส้นทางที่ไม่มี preset ต้อง fail closed โดยแสดงแผนที่ทั่วไปและข้อความให้ใช้ป้ายฉบับอนุมัติ ห้ามเดาเส้นทางหรือเลือกทางผ่านประตูล็อค

## เอกสารสำหรับพิมพ์

สร้างเอกสารแยกประเภทจาก SVG/manifest ชุดเดียวกัน:

1. แผนผังทางหนีไฟต่อ `MapStation`
2. แผนผังพื้นที่ติดเชื้อ–พื้นที่สะอาด–พื้นที่เสี่ยง
3. แผนผังนำทางบุคคลภายนอกและจุดสแกนนิ้วมือ

รองรับ A3 แนวนอน A4 PDF และ PNG ความละเอียดสูง แต่ละฉบับต้องมี:

- ชื่อ/ประเภทแผนผัง
- ตำแหน่ง “ท่านอยู่ที่นี่” เมื่อต้องใช้
- legend
- รหัสเวอร์ชันและวันที่มีผล
- วันที่พิมพ์
- จุดติดตั้ง
- ผู้ตรวจสอบและผู้อนุมัติ
- QR เปิดฉบับเว็บล่าสุด

ห้ามรวม layer ทั้งหมดไว้บนแผ่นเดียว เพราะสีเขตติดเชื้อ เส้นทาง และสถานะเครื่องมือจะทับกัน แผนผังทางหนีไฟใช้พื้นห้องโทนอ่อนและเน้นเส้นทาง/ทางออก

## Schema และ integration

สร้าง migration ที่รองรับอย่างน้อย:

- ตารางพื้นที่ โซน ความสัมพันธ์โซน–พื้นที่ และความสัมพันธ์พื้นที่/โซน–หน่วยงาน
- ตาราง access points/map stations และ map version metadata
- ตาราง assignment บุคลากร–พื้นที่/โซน
- คอลัมน์พื้นที่/โซนใน `equipment`
- checkout secret hash และ checkout method ใน Visitor Log หรือ child table ที่มี lifecycle เดียวกัน

Geometry และ route coordinates ไม่ต้องแก้ผ่านฐานข้อมูลใน Phase 1; อยู่ใน SVG/manifest ที่ review ผ่าน Git การ seed รหัสพื้นที่ในฐานข้อมูลต้อง idempotent และ validator ต้องตรวจความตรงกัน

ข้อมูลเครื่องมือเดิมไม่ถูกบังคับให้ map ครบก่อน deploy การ backfill ทำแบบทยอยและมีรายงาน unassigned ส่วนข้อมูลบุคลากรใช้ profile เดิมและเก็บเฉพาะ assignment เพิ่มเติม

## Error handling และ fail-safe

- ไม่พบ destination mapping: ให้เลือกปลายทางหรือแสดงแผนที่ทั่วไป ห้ามเดาจุดสแกน
- ไม่พบ/ไม่ผ่าน validation ของ route preset: ไม่วาดเส้นทางและไม่หาเส้นทางใหม่เอง
- SVG โหลดไม่ได้: แสดงภาพ fallback ฉบับอนุมัติและข้อมูลติดต่อสำนักงาน
- cookie checkout ใช้ไม่ได้: แนะนำให้เจ้าหน้าที่ปิดรายการแทนโดยไม่เปิดเผย public search
- เครื่องมือ/บุคลากรยังไม่ map: อยู่ใน unassigned report และยังปรากฏในโมดูลต้นทาง
- manifest กับ SVG ไม่ตรงกัน: build/test ต้องล้มเหลว
- แผนผังยังไม่มีผู้อนุมัติหรือ version metadata ไม่ครบ: ส่งออกได้เฉพาะ preview ที่มี watermark “ร่าง” ห้ามส่งออกเป็นฉบับใช้งานจริง
- ไฟฟ้าหรือเครือข่ายใช้ไม่ได้: ใช้ป้ายพิมพ์ประจำจุด เว็บไม่ใช่ dependency ของการอพยพ

## Accessibility และ responsive behavior

- ห้อง/โซนที่กดได้ต้องใช้ semantic button/link หรือ SVG element ที่ keyboard ใช้งานได้ พร้อมชื่อที่ screen reader อ่านได้
- มี focus ring ชัดเจนและ target อย่างน้อย 44 px บนมือถือ
- ไม่ใช้สีเป็นช่องทางเดียวในการสื่อประเภทพื้นที่หรือสถานะ
- รองรับ zoom/pan โดยไม่บังคับ gesture ที่ซับซ้อน และมีปุ่ม reset view
- บนมือถือ detail panel เปิดเป็น bottom sheet; desktop ใช้ side panel
- เคารพ reduced-motion และไม่ใช้ animation กระพริบในโหมดความปลอดภัย

## การตรวจสอบอัตโนมัติ

Validator และ tests ต้องครอบคลุม:

- รหัสห้อง โซน จุด และ route ไม่ซ้ำและมี reference ครบ
- SVG/manifest/seeded space codes ตรงกัน
- ไม่มี edge ผ่านประตู `permanently_locked`
- visitor route ทุกเส้นสิ้นสุดที่ fingerprint checkpoint และไม่ข้ามเขตควบคุม
- Central Lab สี่งาน map ไปฝั่งและ checkpoint ที่ถูกต้อง
- BSL2 Enhance และ PCR อยู่ภายใต้งานจุลชีววิทยา
- โซนคลังวัสดุรวมพื้นที่จริงทั้งสามแห่ง
- ทุกพื้นที่มี infection-control classification
- ทุก `MapStation` ที่เผยแพร่มีตำแหน่ง “ท่านอยู่ที่นี่” และ evacuation preset
- public API ไม่ส่ง personnel/equipment/private metadata
- self checkout ใช้ได้เฉพาะ credential ของรายการตนเอง ใช้ซ้ำไม่ได้ และ staff checkout ยังทำงาน
- permission ของหน้าเจ้าหน้าที่และ API ตรงกัน
- equipment unassigned ไม่หายจากผลรวม
- PDF/PNG A3/A4 มี legend, version, effective date และ approval metadata

## การยอมรับในสถานที่จริง

ก่อน publish เวอร์ชันแรก ต้อง:

- เดินตรวจเส้นทางจากสำนักงานไปยัง fingerprint checkpoint ทุกจุด
- ตรวจเส้นทางหนีไฟจากทุก `MapStation` กับผู้รับผิดชอบความปลอดภัย
- ตรวจ Central Lab ซ้าย/ขวา โซน PPE และโซนคลังวัสดุทั้งสามพื้นที่
- ยืนยันว่า route ทุกชนิดไม่ผ่านประตูล็อคถาวรบริเวณห้องควบคุมไฟฟ้า
- ทดสอบลงทะเบียนเข้า เปิดลิงก์เดิม และ self checkout บนอุปกรณ์จริง
- ตรวจความอ่านง่ายของฉบับ A3/A4 ในระยะติดตั้งจริง
- ตรวจ classification ติดเชื้อ/สะอาด/เสี่ยงกับผู้รับผิดชอบ
- บันทึกผู้ตรวจสอบ ผู้อนุมัติ และวันที่มีผลใน `MapVersion`

## เกณฑ์สำเร็จ

- บุคคลภายนอกสแกนครั้งเดียว ลงทะเบียนเข้า เห็นจุดหมายถึง fingerprint checkpoint และบันทึกออกจากหน้าเดิมได้
- เจ้าหน้าที่ค้นหาห้อง หน่วยงาน บุคลากร และเครื่องมือระดับห้อง/โซนได้โดยไม่เห็นข้อมูลเกินสิทธิ์
- แผนที่แยกความหมายของเขตติดเชื้อ สิทธิ์เข้า สถานะเครื่องมือ และทางหนีไฟออกจากกัน
- ฉบับเว็บและฉบับพิมพ์ใช้ geometry/route version เดียวกัน
- ระบบไม่สร้างเส้นทางผ่านประตูล็อคถาวรและไม่เดาเส้นทางหนีไฟ
- แผนผังที่เผยแพร่ทุกฉบับผ่านการตรวจสถานที่จริงและมี approval metadata ครบ
