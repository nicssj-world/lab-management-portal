# Chemical SDS Publication Copy and Delta Design

## Goal

ทำให้ workflow การเผยแพร่ SDS ในทะเบียนสารเคมีสื่อความหมายตรงกับการใช้งานจริง โดยแยกการเผยแพร่ครั้งแรกออกจากการอัปเดตเฉพาะรายการที่เปลี่ยนแปลง และทำให้สารเคมีในห้องเก็บสารเคมีเห็นชัดว่าเผยแพร่อัตโนมัติ

## Approved wording

คำบนปุ่มต้องใช้ตามนี้เท่านั้น:

- งานที่ยังไม่เคยเผยแพร่: `เผยแพร่ทั้งงาน`
- งานที่เคยเผยแพร่แล้วและมีรายการรออัปเดต: `อัปเดตการเผยแพร่ (N รายการ)`
- งานที่เผยแพร่แล้วและไม่มีรายการค้าง: `ยกเลิกเผยแพร่ทั้งงาน` เมื่อต้องการยกเลิก

ข้อความประกอบเมื่อมีรายการค้าง:

`มีการเปลี่ยนแปลงรอเผยแพร่ N รายการ`

ห้ามใช้คำว่า `เผยแพร่การเปลี่ยนแปลง` หรือ `เผยแพร่การเปลี่ยนแปลงทั้งหมด` ใน workflow นี้

## Behavior

### SDS ตามหน่วยงาน

1. การเผยแพร่ครั้งแรกยังใช้ปุ่ม `เผยแพร่ทั้งงาน` และใช้ endpoint เดิมเพื่อไม่ให้เกิดจุดเผยแพร่ซ้ำ
2. ระบบเก็บเวลาการเผยแพร่ล่าสุดแยกจากสถานะ draft/published เพื่อระบุได้ว่างานเคยเผยแพร่แล้ว แม้การเพิ่ม publication ใหม่จะทำให้สถานะปัจจุบันกลับเป็น draft
3. จำนวนรายการค้างคำนวณจาก active publication ของงานที่ถูก link หลัง baseline ล่าสุด หรืออ้างอิง SDS version ที่ถูกแก้ไขหลัง baseline ล่าสุด โดยนับ publication แต่ละรายการเพียงครั้งเดียว
4. เมื่อมีรายการค้าง ปุ่มจะเป็น `อัปเดตการเผยแพร่ (N รายการ)` ไม่บังคับให้ผู้ใช้เผยแพร่ไฟล์เดิมซ้ำทีละรายการ และข้อความช่วยจะบอกจำนวนที่รอ
5. เมื่อกดอัปเดต ระบบใช้ endpoint เดิม เปลี่ยนสถานะเป็น published และเลื่อน baseline ล่าสุดเป็นเวลาปัจจุบัน
6. การยกเลิกเผยแพร่โดยผู้ใช้จะล้าง baseline เดิม เพื่อให้การเผยแพร่ครั้งถัดไปกลับไปใช้คำว่า `เผยแพร่ทั้งงาน`

การแก้ไขข้อมูล SDS ในระบบปัจจุบันยังบันทึกตาม workflow ที่มีอยู่และ publication ของรายการถูกปรับตามข้อมูลล่าสุดอยู่แล้ว; delta baseline ทำหน้าที่บอกว่าผู้ใช้ยังไม่ได้ยืนยันการอัปเดตระดับงาน และทำให้ปุ่มสื่อสารกับผู้ใช้อย่างถูกต้อง

### สารเคมีในห้องเก็บสารเคมี

ไม่มีปุ่มเผยแพร่ระดับงานสำหรับ room scope การบันทึกทะเบียนและ SDS มีผลกับรายการห้องโดยอัตโนมัติตาม workflow ปัจจุบัน ผู้ใช้จะเห็นข้อความกำกับ:

- มี publication แล้ว: `เผยแพร่แล้ว · อัปเดตอัตโนมัติ`
- มี SDS ฉบับใหม่: `มีฉบับใหม่ · อัปเดตอัตโนมัติ`
- ยังไม่มี publication แต่พร้อม: `พร้อมเผยแพร่อัตโนมัติ`
- ยังไม่มี SDS/publication: `ยังไม่มีการเผยแพร่ · ต้องแนบ SDS`

ใน modal แก้ไขทะเบียนและ toast หลังบันทึก จะระบุชัดเจนเมื่อรายการเป็น room scope ว่ามีผลทันที/เผยแพร่อัตโนมัติ ส่วน department scope ยังคงใช้ข้อความทั่วไปและปุ่มระดับงาน

## Architecture

- เพิ่ม pure module สำหรับคำนวณ publication summary และข้อความ UI เพื่อให้กติกา `N` และ copy มีเทสต์แยกจาก React component
- repository โหลด `last_published_at` และข้อมูล active publication/version แล้วส่ง `pendingCount` และ `hasPublishedBefore` ไปยัง client
- เพิ่มคอลัมน์ `last_published_by` และ `last_published_at` แบบ nullable โดยไม่เปลี่ยน constraint ของสถานะปัจจุบัน
- ปรับ RPC สถานะ publication ให้ set baseline เมื่อ published และล้าง baseline เมื่อผู้ใช้สั่ง draft เอง การ reset เป็น draft จากการ link publication จะไม่ล้าง baseline
- UI ใช้ summary เดียวกันสำหรับปุ่ม, helper text, toast และสถานะ room

## Error handling

- ใช้ route และ authorization เดิมของการเผยแพร่ระดับหน่วยงาน
- เมื่อ RPC ตอบ error ให้ใช้ข้อความ error เดิมของ route และไม่แสดงผลสำเร็จ/refresh
- ปุ่มอัปเดต disabled เมื่อกำลังส่งคำขอ หรือไม่มีเอกสารที่พร้อมเผยแพร่ตามกติกาเดิม
- ถ้าไม่มี baseline หรือข้อมูลวันที่ไม่สมบูรณ์ ให้ถือว่าไม่พบรายการค้างและใช้ flow เผยแพร่ครั้งแรกอย่างปลอดภัย

## Testing

- ทดสอบ pure summary: ครั้งแรก, มี publication ใหม่, version ถูกแก้, ไม่มีรายการค้าง, ยกเลิกแล้วกลับเป็นการเผยแพร่ครั้งแรก
- ทดสอบ exact Thai copy ของปุ่มและสถานะ room
- รันชุด contract tests ของ chemical safety, TypeScript check และ production build
- ตรวจ diff และค้นทั้ง repository เพื่อยืนยันว่าไม่มีคำต้องห้าม `เผยแพร่การเปลี่ยนแปลง` เหลืออยู่ใน implementation ที่เกี่ยวข้อง
