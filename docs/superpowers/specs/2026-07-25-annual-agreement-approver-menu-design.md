# การรับรองข้อตกลงประจำปีและการยุบเมนู

## เป้าหมาย

ใช้ตำแหน่งในผังองค์กรกลุ่มงานเป็นแหล่งอ้างอิงผู้มีอำนาจรับรองข้อตกลงประจำปี และลดเมนูที่ใช้งานไม่บ่อยโดยไม่ทำให้บุคลากรหาทางเข้าข้อตกลงของตนเองยากขึ้น

## สิทธิ์และการรับรอง

- `profiles.dept_role = 'group_lead'` หมายถึงหัวหน้ากลุ่มงานและเป็นผู้รับรองรอบข้อตกลง
- Admin/Manager เปิดรอบ ติดตามสถานะ ยกเว้นบุคลากร และลบรอบที่ยังไม่มีผู้ลงนามได้
- การมี role ระบบเป็น Admin/Manager อย่างเดียวไม่อนุญาตให้รับรองรอบ
- หัวหน้ากลุ่มงานเข้าหน้ารายละเอียดรอบแบบอ่านและรับรองได้ แม้ไม่ได้มี role ระบบเป็น Admin/Manager แต่ไม่เห็นการสร้างรอบ ลบรอบ หรือยกเว้นบุคลากร
- รองหัวหน้ากลุ่มงาน (`group_deputy`) และหัวหน้างาน (`is_section_head`) ไม่ได้รับสิทธิ์รับรองอัตโนมัติ
- Approval API ต้องอ่าน `dept_role` ล่าสุดจากฐานข้อมูลและปฏิเสธผู้ที่ไม่ใช่ `group_lead` แม้เรียก API โดยตรง
- รับรองได้เมื่อผู้รับทุกคนมีสถานะ `completed` หรือ `exempt` แล้วเท่านั้น หลังรับรองรอบเปลี่ยนเป็น `approved` และล็อกการแก้ไข

## หลักฐานผู้รับรอง

เมื่อรับรอง ให้เก็บ `approved_by`, `approved_at`, ลายเซ็น และ snapshot ที่ประกอบด้วยชื่อ ตำแหน่ง และ `dept_role` ณ เวลารับรอง เพื่อให้หลักฐานเดิมไม่เปลี่ยนเมื่อมีการเปลี่ยนหัวหน้ากลุ่มงานภายหลัง

## การยุบเมนู

- นำเมนูลูก “ข้อตกลงประจำปี” ออกจาก Sidebar กลุ่มบุคลากร
- หน้า “ทะเบียนบุคลากร” เป็นศูนย์รวมทางเข้า:
  - ทุกคนเห็นปุ่ม “ข้อตกลงของฉัน” ไปยัง `/staff/agreements`
  - Admin/Manager เห็นปุ่ม “จัดการข้อตกลงประจำปี” ไปยัง `/staff/personnel/agreements`
  - หัวหน้ากลุ่มงานเห็นปุ่ม “รับรองข้อตกลงประจำปี” ไปยังหน้าเดียวกัน
- หน้าโปรไฟล์ของตนเองยังคงปุ่ม “ทำข้อตกลงประจำปี” เพื่อเป็นทางเข้าสำรอง
- ไม่เพิ่ม route ใหม่ จึงไม่ต้องแก้ protected-path regex ใน `proxy.ts`

## หน้าจัดการรอบ

หน้าจัดการรับข้อมูล capability จาก Server Component:

- `canManageCampaigns`: แสดงการเปิดรอบ ลบรอบ และยกเว้น
- `canApproveCampaigns`: แสดงส่วนลายเซ็นและปุ่มรับรอง

ตารางรอบ รายละเอียดรายชื่อ รายงาน และหลักฐานใช้ร่วมกันได้ทั้งผู้จัดการและหัวหน้ากลุ่มงาน ส่วน API สำหรับการสร้าง/ลบ/ยกเว้นยังใช้สิทธิ์ Admin/Manager ตามเดิม

## การทดสอบ

- `group_lead` รับรองได้ และผู้ที่ไม่ใช่ `group_lead` ถูกปฏิเสธที่ API
- Admin/Manager ที่ไม่ใช่ `group_lead` จัดการรอบได้แต่รับรองไม่ได้
- หัวหน้ากลุ่มงานที่ไม่ใช่ Admin/Manager เปิดหน้ารายละเอียดและรับรองได้ แต่จัดการรายชื่อไม่ได้
- ปุ่มรับรองไม่ทำงานเมื่อยังมีรายการค้าง
- snapshot ผู้รับรองถูกบันทึกพร้อมการรับรอง
- Sidebar ไม่มีเมนูข้อตกลงประจำปี และทะเบียนบุคลากรแสดงปุ่มตาม capability ที่ถูกต้อง
- TypeScript, contract tests และ production build ผ่าน
